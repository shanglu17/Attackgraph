概述

本文依照ASTM F3532标准对ZG-ONE载人无人驾驶航空器系统(以下简称"ZG-ONE")进行初步网络安保风险评估形成报告。本文档内容包括安保范围定义、威胁状态识别、安保风险评估、安保措施和安保架构。本文对应ASTM F3532标准中的PSRA（Preliminary Security Risk Assessment）初步安保风险评估，覆盖ASTM F3532章节6.1和6.2。

本文档适用于证明对ZG-ONE适航审定条款AC-92-XX中关于安保内容的符合性。

本文档适用于零重力ZG-ONE航空器研制过程中的安保分析工作。

术语与缩略语

术语

功能危险性评估：是对民用无人驾驶航空器系统及其子系统的功能进行的一种系统、全面检查，用于识别可能由功能失效或异常的潜在的失效状态（灾难性的、危险的、重大的、轻微的、无安全影响的）。

失效：一种影响组件、部件或单元工作，使其不能完成预期功能的事件，包括功能的丧失和异常。

失效状态：考虑飞行阶段及相关的不利操作、环境条件或外部事件的情况下，由一个或多个失效或错误引起或促成，对民用无人驾驶航空器系统、机组操作、地面人员、空中其他航空器或上述组合产生直接或间接影响的状态。

定性分析：是用客观的、非量化的方式评估民用无人驾驶航空器系统及其子系统的安全性的分析过程。

定量分析：是用量化的方法评估民用无人驾驶航空器系统及其子系统的安全性的分析过程。

无人驾驶航空器系统：是指无人驾驶航空器以及与其有关的遥控台（站）、任务载荷和控制链路等组成的系统。本标准中简称“无人机系统”。

飞行机组：指控制无人驾驶航空器的操控员以及负有必不可少职责的无人驾驶航空器观测员。

安保环境

ZG-ONE运行于低空飞行应用场景中，涉及机载系统与多个外部系统之间的持续数据交互。外部交互对象包括遥控站（RCS）、地面通信单元（GCU）、转发服务器、全球导航卫星系统（GNSS）、实时动态定位系统（RTK）、地面维护设备以及大数据中心、低空监控平台和监控大厅等支撑与监管系统。这些系统通过无线链路或有线接口与机载系统进行信息交换，形成跨域数据交互环境。

从信任属性角度，系统划分为机载核心信任域、机载边界域以及外部不可信域。其中，飞行控制与管理系统（IMC/IMS/FMS/FCS）以及与飞行安全直接相关的动力系统、能源与配电系统、导航系统和应急系统构成机载核心信任域，被视为机载核心信任域，其运行依赖数据的完整性、真实性与时效性保障。通信与外部接口系统、探测与避让系统以及音视频通信系统位于机载边界域，作为外部数据进入机载核心系统的入口，同时构成外部潜在攻击进入机载核心系统的主要入口，其接收的数据需经过必要的验证与约束处理后方可被核心系统使用。

所有外部系统默认处于外部不可信域，其提供的数据可能受到篡改、伪造或重放等攻击。其中，GNSS与RTK作为开放信号源，仅具备有限可信性，其输出数据可能受到干扰或欺骗，但其服务本身不纳入飞机特定安保评估范围；然而，其输入数据在机载系统中的使用以及对飞行功能的影响仍纳入本次安保分析。遥控站、地面通信单元及转发服务器等通信相关系统同样被视为不可信输入源，其发送的控制指令、配置数据及业务数据均需在机载侧进行认证与完整性校验。

地面维护设备作为高权限外部实体，具备软件加载、参数配置及数据访问等能力，虽然不纳入机载系统评估范围，但其接口被视为关键安保入口。该类接口在使用过程中需依赖严格的身份认证、访问控制及完整性保护机制，以防止未授权访问或恶意操作对机载核心系统造成影响。

安保环境假设具体如下：

A1 机载核心系统（IMC/IMS/FMS/FCS）在设计与实现上被认为是可信的，其内部通信不作为攻击入口，但其输入依赖外部验证机制。

A2 机载边界系统（如ACU、DAA等）可能接收来自不可信域的数据，其输入需经过验证后方可被核心系统使用。

A3 所有外部系统（包括RCS、GCU、转发服务器等）均被视为不可信，其发送的数据可能受到伪造、篡改或重放攻击。

A4 GNSS与RTK信号源为开放环境信号，仅具备有限可信性，可能受到干扰或欺骗。

A5 地面维护设备为高权限外部实体，其访问需通过严格认证与授权控制，否则可能对系统完整性造成直接影响。

A6 无线通信链路被视为不安全信道，可能受到窃听、中间人攻击或拒绝服务攻击。

A7 物理访问在正常运行条件下受到控制，但在维护或异常情况下可能被突破。

安保边界

本节定义飞机系统的安保边界，用于识别潜在攻击入口并支撑后续威胁分析。

飞机安保边界定义为：机载系统与所有外部系统之间通过物理或逻辑接口进行数据交互所形成的边界。该边界刻画了不同信任域之间的分界面，所有跨越该边界的数据流均可能引入安全风险，是本次安保分析的重点关注对象。

根据前述系统划分，机载系统构成高可信域及边界域，包括飞行控制与管理系统、动力系统、能源与配电系统、导航系统、探测与避让系统、通信与外部接口系统以及应急系统等；外部系统（包括遥控站、地面通信单元、转发服务器、GNSS/RTK、地面维护设备及各类支撑平台）处于不可信或有限可信域。安保边界即定义为上述机载系统与外部系统之间的交互界面。

结合接口识别结果，安保边界具体体现在以下几类关键接口：

1）无线通信接口：通过机载通信单元（ACU）与遥控站（RCS）、地面通信单元（GCU）及转发服务器之间建立的无线数据链路，用于传输控制指令（CMD）、配置数据（CONFIG）、状态信息（STATE）、告警信息（ALERT）及业务数据（DATA）。该接口直接承载飞行控制与运行管理相关数据，是外部不可信域进入机载系统的主要入口之一。

2）导航信号输入接口：由GNSS及RTK系统向机载导航系统提供定位与时间信息的单向输入接口。尽管相关导航服务本身不纳入飞机特定安保评估范围，其输入数据在机载系统中的使用及其对飞行管理与控制功能的影响仍需重点分析。该接口属于开放信号输入，存在信号干扰与欺骗风险。

3）维护接入接口：通过有线连接（如以太网或总线接口）实现地面维护设备与机载系统之间的数据交互，包括软件加载（LOAD）、参数配置（CONFIG）及诊断数据访问（DATA）等功能。该接口具备较高操作权限，一旦被滥用可能直接影响系统完整性，因此被视为关键高风险安保入口。

上述接口分别承载表4-2中定义的数据流（ACD01–ACD17），构成跨信任域的数据传输路径。特别是从外部不可信域进入机载核心系统的控制类（CMD）、配置类（CONFIG）、加载类（LOAD）以及导航状态类（STATE）数据流，对飞行安全具有直接或间接影响，应作为后续威胁识别与风险分析的重点对象。其中，控制类（CMD）、配置类（CONFIG）及加载类（LOAD）数据流构成对机载核心功能具有直接影响的关键路径，而导航状态类数据流（如GNSS）则通过影响感知与决策间接影响飞行安全。

本分析重点关注从外部不可信域经边界接口进入机载核心信任域的数据流。

整机级数据流

转发服务器在系统中作为通信中继节点存在，不作为独立数据源参与控制或配置生成。大数据平台不直接下发控制。因此，相关数据流统一建模为由遥控站（RCS）发起，并通过不同物理路径（直连链路或经转发服务器链路）传输至机载系统。在威胁分析中，针对不同路径分别评估其安全风险。

根据数据流的特点划分了下面六类数据流：

  1. STATE：描述系统当前运行状态的连续或周期性数据；
  2. ALERT：描述需要响应或提示的告警信息；
  3. CMD：描述直接驱动系统行为的控制信息。在本系统中，来自外部系统（如RCS、转发服务器及维护设备）的控制类数据（CMD）均视为控制请求，而非直接执行指令。该类请求在进入机载系统后，需由综合管理系统（IMS）结合当前系统状态进行合法性校验与决策处理，并在满足安全约束条件后，方可转化为内部执行指令并下发至相关执行系统（如FCS、ECU、BMS）。
  4. CONFIG：描述改变系统运行的策略或参数，但不直接触发动作；
  5. LOAD：描述软件更新或加载数据；
  6. DATA：描述不直接参与控制或状态闭环的业务数据。

数据流抽象视图

在保留整机级（ACD）与系统级（SD）数据流细化描述的基础上，为提高系统级威胁分析与审查可读性，将所有数据流进一步抽象为四类关键路径。

（1）外部系统→机载系统（跨安保边界输入路径）

定义：来自外部不可信或有限可信域的数据，经机载边界系统进入核心信任域的路径，是主要攻击入口。

安全特征：

  • 跨信任域
  • 输入可被伪造、篡改、重放
  • 对飞行控制具有直接或间接影响

关注重点：

  • CMD/CONFIG/LOAD/导航STATE
  • 身份认证、完整性保护、语义约束

（2）机载关键控制闭环（飞行安全核心路径）

定义：机载核心系统之间形成的闭环控制路径，直接决定飞行动作与动力输出，是安全关键路径。

安全特征：

  • 强实时性
  • 闭环反馈
  • 直接影响推力与姿态

关注重点：

  • 指令完整性与合法性
  • 状态反馈真实性
  • 控制约束（包线保护）

（3）感知与决策支持链路（间接影响路径）

定义：为飞行决策提供输入数据的路径，不直接控制执行，但影响控制逻辑。

安全特征：

  • 不直接执行控制
  • 影响决策输入
  • 易被“语义攻击”利用

关注重点：

  • 数据一致性
  • 多源融合校验
  • 异常检测与降级

（4）机载系统→外部系统（输出路径）

定义：机载系统向外部系统输出数据的路径。

安全特征：

  • 信息外泄风险
  • 可被利用构造反馈攻击

关注重点：

  • 数据保密性
  • 输出完整性
  • 访问控制与最小暴露

IMC作为机载核心系统，内部集成综合管理系统（IMS）、飞行管理系统（FMS）和飞行控制系统（FCS）。为提高系统行为描述的结构性与可分析性，采用控制闭环方式对关键功能路径进行建模。尽管IMC内部被假设为可信域，其内部控制逻辑仍需通过包线保护、状态约束及异常检测机制防止由于设计缺陷或非恶意异常导致的控制输出偏离安全范围。

根据功能与安全语义，IMC内部可抽象为三类核心闭环，如表所示。

（1）飞行控制闭环（核心安全闭环）

结构：

  • FMS → FCS（导引指令）
  • FCS → ECU（执行控制）
  • ECU → FCS（状态反馈）
  • FCS → IMS（飞行状态）

作用：实现飞行姿态控制与飞行动作执行，是直接决定飞行行为的核心控制路径。

涉及数据类型：

  • CMD：导引与控制指令
  • STATE：姿态、速度及执行状态
  • ALERT：飞行包线及控制异常告警

安全关键点：

  • 控制指令应具备完整性与合法性约束，防止被篡改或越权生成
  • 执行反馈应真实可信，防止状态伪造或延迟
  • 飞行包线保护机制不可被绕过或抑制

（2）感知融合与决策闭环

结构：

  • 导航系统 / GNSS → FMS（定位与姿态信息）
  • DAA → FMS（环境与障碍物信息）
  • FMS → FCS（决策输出）
  • FMS → IMS（态势与任务信息）

作用：提供飞行所需的定位、环境感知与态势信息，并支撑飞行决策生成，对飞行控制形成间接影响。

涉及数据类型：

  • STATE：位置、姿态、速度及环境感知信息
  • ALERT：避障、导航异常等告警信息

安全关键点：

  • 多源感知数据应具备一致性校验机制，防止单源欺骗影响决策
  • 应具备异常检测能力，以识别干扰或欺骗行为
  • 应对输入数据进行可信度评估，支撑安全决策与降级策略

（3）能源与动力管理闭环

结构：

  • BMS → IMS（电池状态信息）
  • IMS → FMS（能量评估结果）
  • FMS → FCS（控制策略调整）
  • IMS → BMS（控制指令）

作用：实现能量分配与续航管理，并通过影响推力策略与任务规划间接作用于飞行控制。

涉及数据类型：

  • STATE：电压、电流及能量状态
  • CMD：上下电及控制指令
  • ALERT：过压、过流等异常告警

安全关键点：

  • 能源状态数据应防止伪造或篡改
  • 控制指令应受到运行状态与安全策略约束
  • 应防止异常能量管理策略对飞行安全产生不利影响

威胁识别

威胁状态识别

在完成系统定义、安保边界划分以及整机级与系统级数据流分析的基础上，需要对跨信任域数据交互及机载关键控制闭环中的潜在安保风险进行系统化建模。本节通过构建整机级威胁状态表，对可能影响飞行安全的威胁情形进行统一描述与结构化表达，为后续风险评估及安保需求分配提供依据。

威胁状态（TC）的识别遵循“数据流驱动”的分析思路，以已定义的飞机级数据流（ACD）和系统级数据流（SD）为基础，结合四类关键路径（跨安保边界输入路径、机载关键控制闭环、感知与决策支持链路以及输出路径）以及IMC内部三类核心控制闭环，对潜在攻击入口、传播路径及其对系统功能的影响进行逐项分析。重点关注来自外部不可信域的数据在进入机载核心信任域过程中的篡改、伪造、重放及语义操纵风险，以及这些风险在控制闭环中的放大效应。

在威胁建模过程中，每一条威胁状态均明确关联其作用路径（Path）、对应的整机级数据流（ACD）与系统级数据流（SD），并映射至受影响的飞机功能（ACF）。在此基础上，结合功能危害分析（FHA）中定义的失效条件（Failure Condition）及其严重度等级（Severity），建立从“威胁场景”到“安保影响”的可追溯关系。同时，为每一类威胁状态提炼对应的安保需求（Security Requirement），以支撑后续系统级安保目标分解与验证活动。

需要说明的是，本节威胁状态表并非对所有可能攻击手段的穷举，而是基于系统架构、信任假设及关键数据流所抽象出的代表性威胁模式，重点体现对飞行安保具有直接或间接影响的关键风险路径。通过这种结构化建模方式，可在保证分析覆盖性的同时控制复杂度，使威胁分析结果具备良好的可读性、一致性和可验证性，并能够直接支撑适航审查中的一致性与可追溯性要求。
