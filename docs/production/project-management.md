# 项目管理与分析历史

## 项目列表

页首新增“项目列表”筛选，默认显示活动业务项目。可切换到“历史演示 / 测试项目”“已归档项目”“回收站”或“全部项目”。同名项目显示名称、项目编号、UUID 前八位及状态；展开“项目管理（归档、回收站与恢复）”可查看完整项目和修订 UUID。

历史样例识别使用明确的既有项目编号规则（例如两个 Phase3 编号、Phase4 演示编号、Phase5 演示及集成测试编号、VG1 和既有 UI 验收编号），不根据项目名称猜测。现有数据不会被清理或迁移；已选择的项目不在筛选范围时仍保留选择并提示，避免切换筛选意外丢失草稿。显式的 `project_kind` 元数据优先于兼容规则。

## 归档、删除与恢复

1. 从项目列表选择目标项目，展开“项目管理（归档、回收站与恢复）”。
2. 核对完整 UUID、项目编号、修订数、资产数和分析运行数。
3. 在“输入项目编号确认”中输入完整编号，并填写至少三个字的操作原因。
4. 点击“归档项目”后，项目只读，仍可查看已有模型和结果。恢复编辑时切换到“已归档项目”，选中项目后点击“恢复为活动项目”。
5. 点击“删除项目（移入回收站）”后，项目从活动列表移除，本地该项目的草稿和选择缓存清除。服务端模型、来源、分析结果、冻结基线和审计均保留。
6. 恢复时切换到“回收站”，选中项目，确认编号及原因后点击“从回收站恢复”，再选择需要查看的修订。项目回到删除前的活动或归档状态；如果仍归档，可再单独恢复为活动项目。

本功能不提供物理清库，只能恢复通过回收站入口删除的项目；此前后台物理删除的项目仍需使用当时的备份恢复。恢复项目不会解除修订冻结，也不会将历史分析变成当前结果；当前性仍按模型、配置和参数核对。项目版本发生冲突时停止操作，使用“刷新项目范围”核对新状态后重新确认；不会自动覆盖。

回收站项目仍占用原项目编号；需要继续使用同一编号时，请恢复原项目。没有删除或隐藏数据库中的历史样例，筛选只改变列表显示。

## 分析历史

进入项目时只读取模型和历史摘要，每页最多 20 条。数据导入、变更管理不预读路径结果。在图谱分析或报告中心选择运行后，只读取该次运行的结果；报告中心有“加载更多历史运行”，不会一次读取全部历史。

报告中心展开“查看此运行的输入快照、评分和诊断（历史保留）”后，可点击“加载完整输入快照”。完整 JSON/Excel 导出仍由服务端核验当前性，JSON 导出包含完整快照，不受界面分批读取影响。

列表、单次结果和完整输入读取分别有加载和失败反馈。结果加载失败可点击“重试加载分析结果”。“待查看”表示摘要尚不足以证明当前性；只有实际加载且通过模型、配置、参数和来源匹配的运行才显示“当前”并允许导出。

## 新增接口

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/v2/governance/workspaces?view=management.v1` | 包含归档及回收站项目的列表，新增项目版本、状态和类别 |
| `GET /api/v2/governance/projects/:id/overview` | 项目范围及操作确认预览 |
| `POST /api/v2/governance/projects/lifecycle` | 归档、回收、恢复 |
| `GET /api/v2/analysis/runs/summaries` | DPS 历史摘要，`project_id`、`revision_id`、`limit`（1–100，默认20）、可选 `cursor` 或 `run_id`（用于恢复先前选中的运行摘要） |
| `GET /api/v2/analysis/runs/detail` | 单次运行结果，范围字段及 `run_id`；可选 `include_inputs=true` |

生命周期命令契约：

```json
{
  "project_id": "项目 UUID",
  "expected_project_version": 1,
  "actor": "workbench-user",
  "command_id": "唯一命令编号",
  "action": "archive",
  "confirmation": "完整项目业务编号",
  "reason": "项目阶段完成"
}
```

`action` 可为 `archive`、`delete`、`restore`。所有命令原子校验项目版本、状态、确认编号，生成审计及幂等回执；同一命令编号不能用于不同请求。项目锁先于修订锁，归档/回收与 v2 修订写入、分析运行、冻结操作串行化。没有修改修订数据版本、评分公式或不可变分析快照。

旧 `GET /analysis/runs` 的默认完整 DTO 和既有调用语义保留；新摘要接口不会返回输入快照或结果载荷。新详情接口默认只包含配置快照与结果，完整输入需显式请求。游标必须属于当前项目、修订和 DPS 方法；外部游标会被拒绝。

这些是可选属性，现有 Neo4j 模型无需新增迁移；`deleted_at` 标记回收，Project 原有 `Active` / `Archived` 状态继续沿用。旧数据不自动打标或删除。
